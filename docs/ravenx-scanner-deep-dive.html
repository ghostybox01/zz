What They Have That We Are Missing

✗ AST-BASED SAST (JavaScript / TypeScript)

Their JS Scanner parses code into an Abstract Syntax Tree and traces data flow from source to sink — detecting XSS, prototype pollution, injection, and insecure API use. Our JS Scanner only runs credential regexes against bundled text. We have zero code flow analysis.

✗ npm SUPPLY CHAIN ANALYSIS

Their JS Extended detects typosquatted packages, dependency confusion attacks, malicious postinstall scripts, and behavioural anomalies across the full transitive npm dependency tree. We have nothing equivalent — our "JS Extended" scans inline HTML scripts for credentials.

✗ CVE / NVD INTELLIGENCE ENGINE

Their NVCA Scanner generates an SBOM from a codebase and cross-references every component against NIST NVD's 260,000+ CVEs with CVSS scoring. We have no CVE database integration — our "NVCA" refers to Node/Vue/Next/Nuxt framework config scanning.

✗ REPO-TO-SOURCE INTEGRITY VERIFICATION

Their R2S verifies that distributed package tarballs match their declared source code — the class of attack that enabled the XZ Utils backdoor (CVE-2024-3094). Our "R2S" is an active Next.js CVE exploit chain — completely different.

✗ LICENSE COMPLIANCE (GPL / COPYLEFT DETECTION)

Their GPL Scanner audits dependency licenses for copyleft risk — AGPL, GPL v2/v3, LGPL — protecting proprietary codebases from inadvertently shipping code that requires open-sourcing. We have no license scanning. Our "GPL" scans GraphQL endpoints.

✗ FALSE POSITIVE PREVENTION ENGINE

Their FPP Scanner uses reachability analysis, VEX documents, and ML confidence scoring to cut 70–80% of noise from raw scanner output. We have no false positive suppression layer — every hit from our regex scanners is treated equally regardless of exploitability.

✗ FULL GIT HISTORY TRAWL

Their Git Scanner forensically walks every branch, tag, stash, and commit since repo inception. Our ScanRepo() does a shallow clone (--depth 1) of HEAD only — we miss credentials that were committed and "deleted" in subsequent commits.

Scanner 01 · Mass Discovery Engine

⚡  Prefilter Mode

The fast first-pass engine. Given a list of millions of domains/URLs, the prefilter probes 5 common .env file paths at 500+ concurrent goroutines and records every HTTP 200 response. No credential extraction happens here — it purely identifies which hosts expose sensitive files, building the queue for the deep scan phase.

Flow
1

Read URL list

Ingests the input .txt file line by line. Supports checkpointing — resumes from last processed line on restart. Distributes across worker fleet via --offset / --limit flags.

2

Concurrent HTTP probes

500 goroutines each grab a domain, construct the 5 .env URLs, fire HEAD/GET requests with 20s timeout. Respects per-domain rate limiting to avoid triggering WAFs.

3

Record 200 hits

Any HTTP 200 response is written to prefilter_hits.txt with the full URL and response size. Non-200 responses are discarded without logging.

4

Queue for deep scan

The hits file becomes the input for the next scan session where full credential extraction runs. This two-phase approach means the expensive extraction only runs on confirmed live .env files.
